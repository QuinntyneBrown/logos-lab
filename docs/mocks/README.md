# Logos Lab mocks

Static HTML mocks of every Logos Lab page, dialog and notification, in every state. They are built only
from the design system in `docs/design-system/` (the Banaro look: oat and birch neutrals, one sage accent,
Manrope).

Open `index.html` from disk to see the gallery. Each mock has a mock bar that links its sibling states.
- **Dark theme:** press `t`, or add `?theme=dark`.
- **Hide the mock chrome:** add `?chrome=0`.

Every mock traces to the L2 requirements in `docs/specs/L2.md` through its `mock:requirements` meta and the
coverage matrix below.

## Open questions

These are the assumptions the mocks make. Each item notes what would change if the answer were different.

1. **Email templates** (L2-092, about 20 messages) are not mocked. Their landing pages are mocked: verify
   email, reset password, invitation, unsubscribe, restore account, export download, account notice and
   cohort join.
2. **Settings** use one shell with section navigation (Profile, Email and password, Security, Sessions,
   Notifications, Privacy and messaging, Your data, Blocked members). Each section has its own route, and
   the spec does not name them.
3. **Studio** is one editor shell (workflow bar, autosave, history) with a body per type. Module and video
   settings live on their package and media screens, so there are no separate module and video editor
   pages.
4. **The notification centre** is a popover panel that becomes a full-screen sheet under 640px. There is
   no `/notifications` page.
5. **Search** is `/search`. The catalogue is `/explore`. The nav links "Courses" and "Collections" open
   `/explore` already filtered.
6. **Suspended and banned members** (L2-090) appeal from an emailed link to `/account/notices/{id}`,
   which works signed out.
7. **Comments held for new accounts with links** (L2-062) appear in a "Held for review" view of the
   moderation queue.
8. **Certificate revocation** (L2-032) is done from the admin user page.
9. **The waitlist offer** (L2-054) is both an in-app dialog and a notification with an action.
10. **`/admin` has a landing page.** Editors see Featured and Analytics. Administrators see everything.
11. **There are two audit trails**, moderation (L2-089) and administration (L2-099), on separate pages.
12. **There is no attendee check-in screen.** The spec counts attendance (L2-101) but defines no check-in
    UI.
13. **The maintenance page** (503) is derived from "announced maintenance" (L2-135). No requirement asks
    for it directly.
14. **The theme control** is a header menu for visitors and an item in the account menu for members.
