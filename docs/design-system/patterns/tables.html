Data tables and lists

Show many things so they are easy to scan, compare and act on, at every width.

Pattern

Overview

Choose the shape by what people do with the items. Compare values across columns: a table. Read and open items one by one: a list of rows. Browse with pictures and a few facts: cards in a grid. Whatever the shape, the same frame sits around it: a search and filter toolbar with a visible count above, and pagination or Show more below.

When to use

  • Table: people compare the same attributes across many items (status, owner, dates, counts), sort by columns, or select several items to act on together.
  • Rows list: items are read one at a time, with a title and a line of detail: notes, messages, activity.
  • Card grid: items are recognised by a picture or a mark as much as by name: people, projects.
  • Not a table for layout, for a single record (use a description list), or for fewer than about three items.

Structure

  1. Toolbar — search, filters and sort, with the result count as a sentence ("4 of 48 notes").
  2. Active filters — removable pills, so people can see and undo what narrowed the list.
  3. Bulk bar — appears only while items are selected, above the collection, and names the count.
  4. Collection — a captioned table, a list of rows or a grid of cards.
  5. Paging — numbered pages for stable lists, Show more for feeds.

States

  • Loading: skeleton rows or cards in the final layout; the toolbar stays usable.
  • Refreshing: current rows stay, the count says "Updating…", and new results replace them in place.
  • Empty and no results: an empty state in the collection's place, with Clear filters when filters caused it. The toolbar stays.
  • Sorted: the sorted column's header carries aria-sort and shows its direction; only one column at a time.
  • Selected: rows tint sage and the bulk bar names the count. Select-all becomes mixed when only some rows are selected.
  • Failed: an inline error in the collection's place with Try again; search terms and filters are kept.

Responsive behaviour

  • 360px: prefer a rows list or cards. When a table is the right shape, it scrolls sideways inside .table-wrap, with the first column as the row's name; the page itself never scrolls sideways. The bulk bar wraps its buttons; filters move into a bottom sheet behind a Filters button.
  • 768px: card grids go to two columns; tables show their full width when it fits.
  • 1024px and up: filters sit in a column beside the results; card grids go to three or four columns.

Long names and labels wrap; never truncate the one piece of text that identifies an item.

Accessibility

Tables: a native <table> with a <caption> (visually hidden if a heading already says it) and <th scope="col"> headers. Use scope="row" when the first cell names the row. Don't add grid roles to a table people only read.

Sorting: the header holds a button; the th carries aria-sort="ascending" or "descending".

Selection: every checkbox is labelled with the item's name ("Select Field Day checklist"); select-all is labelled for the collection and uses the mixed state. Announce the selected count in a status region.

Row actions: each names its object ("Archive Field Day checklist"), since a screen reader hears many identical buttons otherwise.

Lists: use real ul and li so the count is announced. Result counts live in a role="status" region.

KeyEffect
TabMoves through the links, checkboxes and buttons in reading order.
SpaceToggles the focused row checkbox.
EnterOpens the focused item or activates a sort header.

Content

  • Counts are numerals in a sentence: "4 of 48 notes", "2 notes selected", "Showing 25–48 of 120".
  • Column headers are short nouns in sentence case: Title, Last edited, Words. Units go in the header, not every cell.
  • Dates are relative when recent ("Today, 9:40 am", "Yesterday") and absolute after that ("Wed 7 Oct").
  • Empty cells show an em dash or "Not set", never a blank.
  • Numbers align right and use tabular figures, with thousands separators (1,284).
