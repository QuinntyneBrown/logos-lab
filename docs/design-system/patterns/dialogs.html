Dialogs and overlays

Ask for one focused decision on top of the page, then return the person exactly where they were.

Pattern
  • Overview
  • When to use
  • Structure
  • States
  • Responsive behaviour
  • Accessibility
  • Content
  • Do and don’t
  • Sources

Overview

An overlay borrows the person's attention for a moment. Use it for one short, focused task: confirm a deletion, send a quick note, pick from a few options. Name the task in the title, keep the safe choice first and the decision last, and when it closes, put focus back on the control that opened it. Anything longer than a few fields, or anything a person might want to bookmark, is a page.

NeedUse
Confirm a destructive or consequential actionDialog, small, with a danger button
A short task with one to three fieldsDialog
Filters or options on a phoneSheet from the bottom
A few actions for one objectMenu
A short, non-blocking explanation or quick actionPopover
A name for an icon-only buttonTooltip
Long editing, many fields, or anything shareableA page

When to use

  • Confirmation before something that can't be undone, or that affects other people.
  • Quick tasks that make sense without leaving the page: rename, send a note, invite one person.
  • Not for information a person needs while doing something else (use an inline message or a popover), for a success message (use a toast), or for a dialog opened from another dialog.

Structure

A dialog has three parts:

  1. Header — an optional icon tile, the title as a question or task ("Delete Northwind?", "Invite to Northwind"), and a close button.
  2. Body — one or two sentences saying exactly what will happen, then any fields. It scrolls if it must; the header and footer don't.
  3. Footer — the safe action first (Cancel, Keep project), the decision last. Only one primary or danger button.

States

A dialog moves open → busy → closed, or open → invalid / failed and stays open.

  • Open: focus moves to the first field, or to the safe action when there are no fields. Never to the danger button.
  • Busy: the decision button shows a spinner and a present-tense label; fields become read-only; the safe action stays until the request is sent.
  • Invalid: errors appear beside the field, and the dialog stays open.
  • Failed: an alert at the top of the body explains what happened. Every answer is kept.
  • Done: the dialog closes, focus returns to the opener, and a toast confirms the outcome.

Responsive behaviour

  • 360px: dialogs rise from the bottom as full-width sheets with rounded top corners; footer buttons wrap and stay above the safe area. Menus and filter panels become bottom sheets too.
  • 640px and up: dialogs centre over a dimmed backdrop at their capped width (small for confirmations, medium for short tasks).
  • 1024px and up: filter sheets usually become a side column on the page and stop being overlays at all.

The body scrolls inside the dialog when it is taller than the screen; the title and actions stay in view.

Accessibility

Role: use a native <dialog> opened with showModal(), or role="dialog" with aria-modal="true" while the page behind is truly inert. Name it with aria-labelledby (the title) and describe it with aria-describedby (the consequence sentence). The static specimens on this page are labelled regions.

KeyEffect
Tab / Shift+TabMoves between controls inside the dialog only.
EscapeCloses the dialog without acting, like Cancel.
EnterActivates the focused button; never the danger action by default.

Focus: on open, to the first field or the safe action. On close, back to the control that opened it.

Menus: role="menu" only for real action menus with arrow-key support; a list of links stays a nav.

Motion: the rise-in animation is removed under reduced motion.

Content

  • Title: a question for a confirmation ("Delete Northwind?"), a task for anything else ("Invite Grace Liu to Northwind"). Name the object.
  • Body: what will happen, to what, for whom, and whether it can be undone. "This permanently deletes the project, its 48 notes and the Field Day gathering for all 14 members."
  • Buttons: the decision repeats the verb from the title (Delete project); the safe choice says what it keeps (Keep project, Stay) or simply Cancel. Never Yes / No or OK.
