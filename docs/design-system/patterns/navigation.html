Navigation and page structure

Keep every page in the same calm order, so people always know where they are and how to get back.

Pattern
  • Overview
  • When to use
  • Structure
  • States
  • Responsive behaviour
  • Accessibility

Overview

Every page is built in the same order: skip link, top bar, page title with its one main action, content, footer. The top bar names the same few destinations in the same order on every page; the current one is marked. Detail pages add a breadcrumb back to their parent. Peer views of one object use tabs; settings and admin areas use a side navigation.

The specimen below shows the top bar and the start of main; in a page the .skip-link comes first and the content sits in main#main.

When to use

  • Top bar: on every page, signed in or out. Four to six destinations; anything more goes in a menu or a section page.
  • Breadcrumb: on detail and edit pages that sit below a list (Projects / Northwind / Edit). Not on top-level pages, where it would only repeat the top bar.
  • Page header: on every page, with exactly one h1 and at most one primary action.
  • Tabs: for two to six peer views of the same object (Overview, Notes, People). Not for steps in a sequence; use a stepper.
  • Side navigation: for settings and other areas with more than five sections.
  • Pagination: for long, stable lists people page through; "Show more" for feeds.

Structure

Source order matches visual order:

  1. .skip-link → #main, the first focusable element on the page.
  2. header.header with the brand, nav[aria-label="Primary"] and account actions.
  3. main#main, containing an optional breadcrumb, then .page-head with eyebrow, title, one-line lead and actions.
  4. The page's content, in sections that each start with a heading.
  5. footer.footer with secondary links.

States

  • Current: the active destination carries aria-current="page" and shows the small sage dot (top bar), the sage underline (tabs) or the tinted row (side navigation). The current breadcrumb item is plain text.
  • Hover and focus: links gain a linen wash and the shared focus ring; nothing moves.
  • Collapsed: below 1024px the primary navigation sits behind a Menu button that opens a popover; it closes on Escape, on selection and with its own Close menu button.
  • Counts: unread counts sit on the icon and are part of the accessible name ("Notifications, 3 unread").
  • Signed out: the same destinations in the same order, with Sign in and Join in place of the account button.

Responsive behaviour

  • 360px: the brand, account button and a round Menu button fill the bar; destinations live in the menu popover. Breadcrumbs may show only the nearest parent ("← Projects"). Tabs scroll sideways rather than wrap. Settings links become a horizontal scrolling row.
  • 768px: the Menu button shows its label. Page header actions move beside the title.
  • 1024px and up: destinations sit inline in the top bar; the menu button disappears. Settings navigation becomes a vertical column beside the content.

The page title and its primary action are never hidden behind a menu at any width.

Accessibility

Landmarks: one header, one main with id="main", one footer. Every nav has a distinct aria-label: Primary, Breadcrumb, Settings, Pagination, Footer.

Skip link: first in the source, visible when focused, and moves focus to main.

Current page: aria-current="page" on the active link, never only a colour change.

Menus are lists of links: a navigation popover is a nav with a list of links, not role="menu". Tabs use the full tab pattern (role="tablist", arrow keys move between tabs, Tab moves into the panel).

KeyEffect
TabMoves through skip link, top bar, main content, footer, in that order.
EnterFollows a link or opens the Menu popover.
EscapeCloses the Menu popover and returns focus to the Menu button.
Left / Right arrowMoves between tabs in a tablist.

Focus after navigation: on a client-side route change, move focus to the new page's h1 (or to main) and update the document title.

Touch: every navigation target is at least 44px tall.

Content

  • Destinations are short, plural nouns that match the page titles they lead to: Projects, Notes, Gatherings. Use the same words in the top bar, breadcrumbs, page titles and emails.
  • Page titles name the thing, not the action: "Northwind", "Notifications", "Edit Northwind".
  • Leads are one sentence of context: "Planning the spring field season with 14 people."
  • Breadcrumbs use the parent pages' titles exactly.
  • Never rename or reorder destinations between signed-out and signed-in pages.
