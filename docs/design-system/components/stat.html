Stat and KPI

Show a few numbers that matter, large and light, with a plain label underneath. Hairlines divide them; nothing shouts.

Standard componentContrast verified

Overview

Use a stat row (.stats) for the two to four numbers that summarise a page — on a home page, a project overview or a report. Use the compact KPI list (.kpis) inside a card or aside, where the numbers support something else. Show a number only when people will act on it or feel something about it; a table is better for comparing many values, and a progress bar is better for "how far along".

Used in 1 mock state.

Anatomy

  1. Valuethe number in the light display face, tabular figures, --font-size-3xl (--font-size-2xl in a KPI list).
  2. Labela short noun phrase in muted body text under the value.
  3. Trendoptional: the change since the last period, in words and a sign, coloured by whether it is good or bad.
  4. Dividershairlines above and between items; on wide screens the row sits on one line with vertical rules.

Sizes

stats use one display size per form — --font-size-3xl in a row and --font-size-2xl in a KPI list. Do not scale a number up to make it feel important; give it the first position instead.

States

A stat is passive. While numbers load, set aria-busy="true" on the .stats row or .kpis list: each value and trend becomes a soft shimmering bar at its final size, so labels stay readable and nothing moves when the numbers arrive. If a number cannot load, show "—" with the label and explain once nearby; never show 0 for unknown.

Responsive behaviour

At 360px and 768px a stat row shows two items per line, divided by hairlines under each item. From 1024px all four sit in one row with vertical hairlines between them and more vertical room. A pair (.stats--pair) and a KPI list stay two columns at every width. Long labels wrap under the value; values never wrap.

Theming

Values use --color-fg-default, labels --color-fg-muted, trends the success and danger text roles, and dividers --color-border-default; every one has a dark value, so the row needs no dark-mode rules.

Accessibility

Role: a stat row is a list (role="list" with role="listitem" items, or a real <ul>) with an aria-label that says what is being counted and when. A KPI list is a <dl> so each label is tied to its value. Neither is a focus stop.

Focus: only links inside, such as "See who is coming", take focus.

Labelling: read in order, a stat says value then label ("23 tasks closed"), so write labels that make sense after the number. Trends say the comparison in words — "+6 on last week", "0.6 days faster" — so colour is never the only clue. Use a real minus sign (−) so screen readers say "minus".

Motion: the loading shimmer stops under reduced motion; values never count up.

Touch: N/A for the numbers; any link inside keeps a 24px minimum target.

Content

Numbers use tabular figures, a thousands separator (1,284) and at most one decimal place (1.4 days). Labels are lowercase noun phrases that follow the number: tasks closed, people on the team, days until Field Day. Trends name the comparison: +6 on last week, never a bare "+35%". Round to what people can feel; "about 1,300" is fine on a home page, exact counts belong in reports.

Code

Use .stats with .stats__item children for a row (add .stats--pair for two columns), or <dl class="kpis"> for a compact list. Add .stats__delta (or .stats__delta--down when the change is bad) under a label, and aria-busy="true" on the container while values load.
