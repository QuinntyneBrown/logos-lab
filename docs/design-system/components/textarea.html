Textarea

Room for a longer answer — a project summary, meeting notes, a reply — that grows with what people write.

Overview

Use a textarea when the answer is a sentence or more: a summary, notes, feedback, a message. For a name, a number or anything that fits on one line, use a text field. A textarea always sits in a form field with a visible label, and starts tall enough to show what a good answer looks like — three to five lines.

Kit component; mocks have not been written yet.

Anatomy

  1. Labelfrom the surrounding .field.
  2. Container.textarea: at least 120px tall, medium radius, hairline strong border, resizable vertically.
  3. Textbody size at the normal line height, so long notes stay readable.
  4. Help and counteroptional guidance and a soft character limit under the box.

Sizes

Set the height with rows (3 for a reply, 4–5 for a summary, 8 or more for notes) and let .textarea--grow or the vertical resize handle take it from there. Width always fills the field.

States

Hover darkens the border to the muted role; focus draws the sage ring. Read-only fills with linen and softens the border but keeps the text in the default colour, so it stays easy to read and copy; disabled drops the border and fades the text. Invalid turns the border to danger, tints the fill and adds an error message below, keeping everything the person wrote.

Responsive behaviour

The textarea fills its column at every width. On phones keep rows at 3–4 so the label, the box and the submit button fit above the keyboard. The resize handle stays vertical-only so the layout never breaks sideways.

Theming

Every colour comes from a semantic role, so the dark theme needs no component-specific rules. A light specimen nested under a dark root resets its roles.

Accessibility

Role: native <textarea>, multi-line by definition.

KeyEffect
Tab / Shift+TabMoves into and out of the textarea. Tab never inserts a tab character.
EnterStarts a new line. It never submits the form.
Arrow keys, Home, End, Page Up / DownMove the caret through the text.

Focus: the 2px ring offset 3px wraps the box. Focus never moves out on its own, not even when a character limit is reached.

Labelling: a visible <label for>; help and the counter are linked with aria-describedby. Announce the count politely (aria-live="polite" on a visually hidden copy, updated after typing pauses), not on every keystroke.

Motion: border and fill colour changes only; field-sizing growth is instant and has no animation.

Touch: the whole box is the target. Keep at least 120px of height so the keyboard does not cover the text being written.

Content

  • The label names the content: Project summary, Meeting notes, Reply to Daniel.
  • Help sets expectations about length and audience: "Two or three sentences. Shown at the top of the project."
  • Placeholders may show a starting line in the product's own voice ("Thanks, Daniel — I can bring the maps."), never "Type here…".
  • Errors keep the text and say what is missing: "Write a short summary so the team knows what Northwind is for".

Code

Use textarea.textarea inside a .field and set rows. Add .textarea--grow for notes that should grow with their content.

<div class="field"><label class="field__label" for="s471-ta-summary">Project summary</label><textarea class="textarea" id="s471-ta-summary" name="s471-summary" rows="4" aria-describedby="s471-ta-summary-help">Northwind keeps the team's plans, notes and decisions in one calm place.</textarea><p class="field__help" id="s471-ta-summary-help">Two or three sentences. Shown at the top of the project.</p></div>
