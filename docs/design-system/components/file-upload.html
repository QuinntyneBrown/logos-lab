File upload

Add a file by choosing or dropping it, then see it upload, succeed or fail — with the native chooser always one key press away.

Overview

Use a file upload to attach a document or an image: a cover image for Northwind, the agenda for Field Day, a profile photo. The dashed dropzone is a convenience for pointer users; the native file chooser inside it is the real control and always works with a keyboard, a screen reader and a phone. For a profile photo or logo, use the compact .photo-edit row with the current image and a Change photo button that opens a dialog. Show progress with a progress bar inside the dropzone.

Kit component; mocks have not been written yet.

Anatomy

  1. Labelthe .field label, linked to the file input.
  2. Dropzone.dropzone: a dashed, rounded linen area that accepts dropped files.
  3. Icon tile.dropzone__icon, a sage tile with an upload glyph (decorative).
  4. Prompt.dropzone__title, one line saying what to drop.
  5. Chooserthe native input type="file"; its button is styled as a quiet pill.
  6. Requirementshelp text with formats and size limit, linked with aria-describedby.
  7. File row.dropzone__file: preview or icon, .dropzone__name, .dropzone__meta and actions.

Sizes

One size. The dropzone fills its column and grows with its content; previews are 64px in the file row and 96px in .photo-edit.

States

Dragging tints the zone sage and changes the prompt to "Drop the image to upload it". Uploading replaces the prompt with the file row and a progress bar, with Cancel beside it. Complete confirms in the success role and offers Replace and Remove. Invalid (wrong type or too large) and failed (the upload stopped) both turn the zone to the danger roles with a sentence that says what to do; failed adds Try again. Disabled mutes the border, the tile and the chooser.

Responsive behaviour

The dropzone fills its column at every width. On phones, dragging is rare, so the prompt can read "Choose an image" and the chooser opens the camera roll or files. File rows wrap their actions under the name below 24rem; long file names break anywhere rather than overflow. .photo-edit wraps the text under the photo on narrow screens.

Theming

Every colour comes from a semantic role, so the dark theme needs no component-specific rules. A light specimen nested under a dark root resets its roles.

Accessibility

Role: the native <input type="file"> is the control; the dropzone is a drop target only. Remove and Try again are separate, labelled buttons.

KeyEffect
Tab / Shift+TabMoves to the chooser, then to Replace, Remove, Cancel or Try again.
Enter, SpaceOpens the system file chooser, or activates the focused button.
EscapeCloses the system chooser without changing the selection.

Focus: the ring is on the chooser button. After a file is removed, focus moves to the chooser; after Try again, it stays on the file row.

Labelling: the field label names the input; requirements are linked with aria-describedby. Remove buttons name the file ("Remove park-map.png"). Upload progress uses role="progressbar" with a label; success is announced with role="status" and failure with role="alert".

Motion: the progress bar eases its width over 640ms; under reduced motion it jumps. Nothing else moves.

Touch: dragging is never required (WCAG 2.5.7); the chooser button is the main target on touch screens, 36px tall inside a padded zone.

Content

  • The label names what the file is for: Cover image for Northwind, Attachments for Field Day.
  • State formats and limits before people choose: "JPG or PNG, up to 5 MB."
  • Errors name the file and the fix: "field-day.heic is a HEIC photo. Choose a JPG or PNG."
  • Do not claim success until the upload is processed: "Uploading… 0.8 of 1.4 MB", then "Uploaded".

Code
