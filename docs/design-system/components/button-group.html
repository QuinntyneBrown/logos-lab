Button group

Keep related buttons together — a row of actions, a segmented switcher for views, or a toolbar of toggles.

Overview

A button group keeps a few related buttons together. Use a plain group for two to four actions on the same object (Share, Duplicate, Export). Use the segmented group to switch between two to four views of the same content, where exactly one is on. Use a toolbar for independent toggles such as text formatting. The actions that submit a form belong in .form-actions (see form layout); more than four actions belong in a menu.

Not used in the mocks yet.

Anatomy

  1. Group.btn-group: a wrapping flex row with an 8px gap, role="group" (or toolbar) and an aria-label.
  2. Buttonsordinary .btn buttons; quiet or ghost for secondary actions, at most one primary.
  3. Tracksegmented only: a linen pill (.btn-group--segmented) behind the segments.
  4. Selected segmentaria-pressed="true" lifts it onto the surface with a soft shadow.

Sizes

The group follows its buttons. Add .btn--sm to every button for dense toolbars and table rows, or leave them at the 44px default; never mix sizes in one group.

States

Each button keeps its own hover, focus, active and disabled states. In a segmented group, hovering an unpressed segment deepens the linen; the pressed segment sits on the surface with a soft shadow and moves when another segment is chosen. In a toolbar (.btn-group--toolbar), a pressed toggle fills with the sage wash and accent text, and several can be pressed at once; the focus ring stays distinct from the pressed fill. Disabling the group disables every button in it.

Responsive behaviour

Plain groups and toolbars wrap onto a second line on narrow screens instead of shrinking their buttons. Segmented groups do not wrap: keep them to two to four short labels (one word each) so they fit a 360px screen; with longer labels, use a select on phones.

Theming

Every colour comes from a semantic role, so the dark theme needs no component-specific rules. A light specimen nested under a dark root resets its roles.

Accessibility

Role: role="group" with an aria-label for actions and segmented switchers; role="toolbar" for a set of toggles. Toggle buttons use aria-pressed.

KeyEffect
Tab / Shift+TabMoves between buttons in a group. A toolbar is a single tab stop.
Left / RightIn a toolbar, moves focus between buttons (roving tabindex), wrapping at the ends.
Home / EndIn a toolbar, moves focus to the first or last button.
Enter, SpaceActivates the focused button or toggles it.

Focus: every button keeps the 2px sage ring, including the pressed segment.

Labelling: name the group by its task (Project actions, View, Text formatting). Icon-only toggles need aria-label; the pressed state comes from aria-pressed, never from a changing label.

Motion: background and colour transitions take 240ms; the pressed segment does not slide.

Touch: buttons keep their 44px height (36px with .btn--sm) and the 8px gap prevents mis-taps.

Content

  • Give each button a verb and object, or a one-word view name in a segmented group: List, Board, Calendar.
  • Order actions from least to most important, with the primary last: Discard, Save draft, Publish note.
  • Keep labels parallel in length and grammar so the group reads as one set.

Code

Wrap the buttons in .btn-group with role="group" and an aria-label. Add .btn-group--segmented and aria-pressed for a view switcher; use .btn-group--toolbar with role="toolbar", ghost icon buttons and roving tabindex for toggles.

<div class="btn-group" role="group" aria-label="Project actions"><button class="btn btn--quiet" type="button">Share</button><button class="btn btn--quiet" type="button">Duplicate</button><button class="btn btn--quiet" type="button">Export</button></div>
