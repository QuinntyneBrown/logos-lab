Menu

A short list of actions that opens from a button. Quiet rows on a raised surface, with the destructive action last and set apart.

Core componentContrast verified

Overview

Use a menu for a handful of actions that belong to one object but don't deserve a button each: rename, duplicate or archive a project, or the account actions behind the avatar. Keep it to seven items or fewer. If people need to see the options before they choose, use a select or a radio group. If the list is navigation, use a sidebar navigation or plain links. A menu that asks for more input belongs in a popover or a dialog.

Kit component; mocks have not been written yet.

Anatomy

  1. Triggera button or icon button with aria-haspopup="menu" and aria-expanded; it names the object: More actions for Northwind.
  2. Surfacethe raised panel: --color-bg-surface-raised, hairline border, --shadow-3, 15rem minimum width.
  3. Headeroptional; who or what the menu acts on, such as the signed-in person.
  4. Group labeloptional overline that names a set of items.
  5. Itema 44px row: optional 16px icon, a verb-first label and an optional shortcut hint.
  6. Dividera hairline that sets the destructive item apart.
  7. Danger itemlast in the list, in the danger text role.

Shortcuts

Shortcut hints sit at the trailing edge in the caption role. The item carries aria-keyshortcuts; the hint itself is hidden from assistive technology so it isn't read twice.

Checkable

Radio items pick one option; checkbox items toggle a setting. The check mark (.menu__check) is always in the markup and only shows when aria-checked="true", so labels stay aligned.

Sizes

one size. Items are 44px rows so every action is a comfortable touch target; the surface is at least 15rem wide and grows to its longest label.

States

Hover and keyboard focus on an item add a linen wash (--color-bg-subtle); focus also draws the sage ring. Active (pressed) deepens the wash to the sage tint. A danger item keeps its red label on hover and takes the danger background. Disabled items stay in the list, and in the arrow-key order, with aria-disabled="true" and the disabled text role, so people learn the action exists. Checked radio and checkbox items show the check mark in the accent text role.

Responsive behaviour

The surface opens below its trigger and is aligned to the trigger's nearer edge, flipping above it when there is no room below. It never grows wider than the viewport minus the page margin; long labels wrap rather than truncate. Below 40rem, a menu of more than five items, or one opened from the bottom of the screen, may open as a bottom sheet with the same items. At 768px and 1024px and up nothing else changes.

Theming

Every colour reads a semantic role. In dark mode the surface is the raised charcoal, the wash is a lighter charcoal and the danger label lightens to stay readable; the shadow is deeper so the panel still lifts from the page. There are no component knobs; tint the surface by changing --color-bg-surface-raised.

Accessibility

Role: the trigger is a <button> with aria-haspopup="menu", aria-expanded and aria-controls. The surface is role="menu" named by aria-label or by the trigger (aria-labelledby). Items are menuitem, menuitemradio or menuitemcheckbox with aria-checked; dividers are role="separator"; group labels name a role="group". The .more disclosure is a list of plain links in a named group, not an ARIA menu. This follows the WAI-ARIA APG menu button pattern; CSS alone gives none of the keyboard behaviour below.

KeyEffect
Enter, Space, Down Arrow (on the trigger)Opens the menu and focuses the first enabled item.
Up Arrow (on the trigger)Opens the menu and focuses the last item.
Down Arrow / Up ArrowMoves to the next or previous item, wrapping at the ends. Disabled items are focusable but do nothing.
Home / EndMoves to the first or last item.
A letter keyMoves to the next item whose label starts with that letter.
EnterActivates the item and closes the menu.
SpaceToggles a checkbox or radio item and keeps the menu open; activates any other item.
EscapeCloses the menu and returns focus to the trigger.
TabCloses the menu and moves focus to the next control after the trigger.

Focus: focus moves into the menu when it opens (roving tabindex="-1" on items) and always returns to the trigger when it closes. The 2px --color-focus-ring sits inside the surface's padding, so it is never clipped.

Labelling: the trigger names the object, never just "More": aria-label="More actions for Northwind". Icons are decorative. Shortcut hints are aria-hidden and repeated as aria-keyshortcuts on the item. Use aria-disabled="true", not disabled, so a disabled item is still announced.

Motion: items change colour at once, so the highlight never lags behind the arrow keys. If the app animates the surface open, use the shared settle entrance over --duration-slow; reduced motion removes it and the menu appears at once.

Touch: items are 44px tall and span the full surface width. A tap outside the surface closes it; nothing depends on hover.

Content

Start each item with a verb and keep it to three words: Rename, Copy link, Export as PDF. Name the object on destructive items: Delete Northwind, Remove Daniel from Northwind, not "Delete". Use sentence case and no full stops. Add an ellipsis only when the item opens a dialog that asks for more input (Move to…). Order items by frequency, keep related items together, and put the destructive item last. Write shortcuts as people press them on the platform: Ctrl Z on Windows and Linux, ⌘ Z on macOS.

Code

Render the menu in a popover layer next to its trigger (.menu-anchor under the top bar, or .more__menu inside a .more disclosure). Add .menu__item--danger for destructive items, .menu__check inside checkable items, and aria-disabled="true" to disable an item.
