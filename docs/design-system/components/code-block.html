Code block

Monospaced text on a soft linen panel for commands, settings and snippets people read closely or copy.

Overview

Use a code block for anything people type or paste exactly: a command, a settings file, an address, a key. Inline code marks a short literal inside a sentence; a block holds one or more whole lines and keeps their spacing. Add a copy button when copying is the main reason the block is there. Don't use code styling for emphasis or for product names — use plain text, and badges for status.

Kit component; mocks have not been written yet.

Anatomy

  1. Panel--color-bg-subtle with a medium radius and --space-4 padding (.code-block).
  2. Codethe monospace code style; whitespace and line breaks are kept exactly.
  3. Copy buttonoptional small quiet button after the block (.code-copy).
  4. Statusa polite live region that confirms the copy.

Variants

Block

Several lines, such as a settings file. Indentation is kept exactly as written.

{
  "notebook": "Harbour Notes",
  "format": "markdown",
  "since": "2026-10-01",
  "include_comments": true
}

Inline

A short literal inside a sentence: a command, a file name or a value someone will type.

With copy

A command people will paste into a terminal. The button copies the exact text and a status line confirms it.

notes export "Harbour Notes" --format markdown

Scrolling

A long line scrolls sideways instead of wrapping, so it stays exact. The panel is a focusable, labelled region so keyboard users can scroll it.

https://hooks.example.com/northwind/harbour-notes/v2/events?include=pages,comments,exports&since=2026-10-01T09:00:00Z

Code block · scrolling

Sizes

one size. Code uses --text-code in blocks and inline; inline code drops to --space-1 side padding.

States

Hover and focus show on the copy button like any quiet button, and on a scrolling block focus draws the sage ring around the panel. Copied confirms in the status line and briefly switches the button to a check and Copied; it returns to Copy command after a few seconds. If the clipboard is unavailable, the status line asks people to select the text instead.

Responsive behaviour

Blocks never wrap code: at 360px long lines scroll sideways inside the panel while the page stays still. Inline code wraps with the sentence around it. The copy button sits under the block at every width so it never covers the code.

Theming

The panel uses --color-bg-subtle and the text --color-fg-default, both semantic roles, so code reads at more than 4.5:1 in light and dark themes without a separate syntax palette.

  "notebook": "Harbour Notes",
  "format": "markdown",
  "since": "2026-10-01",
  "include_comments": true

Accessibility

Role: <pre><code> for blocks and <code> inline. A block that scrolls is a focusable region (tabindex="0", role="region") with an aria-label that says what it holds.

KeyEffect
Tab / Shift+TabMoves to the copy button, or to a scrolling block.
Enter, SpaceCopies the code from the focused button.
Arrow keysScroll a focused block sideways.

Focus: the copy button and scrolling blocks show the sage ring. Focus stays on the button after copying.

Labelling: name the button after what it copies (Copy command, Copy address). The status line is role="status", so the confirmation is announced without moving focus.

Motion: none.

Touch: the copy button is 36px tall; on touch screens it is the dependable way to copy, because selecting monospace text by hand is fiddly.

Content

Show exactly what people should type, with no prompt character ($) unless they must type it, and no placeholder they could paste by mistake. Introduce the block with a sentence saying where to use it. Keep a copyable block to one command; split several commands into several blocks.

Code blocks read --color-bg-subtle, --text-code, --radius-md (blocks), --radius-xs (inline) and --space-4 padding.

Code

Use <pre class="code-block"><code>…</code></pre> for blocks and <code class="code-block code-block--inline"> inline. Wrap a block, its copy button and a role="status" line in .code-copy.
