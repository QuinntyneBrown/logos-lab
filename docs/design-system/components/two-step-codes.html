Two-step codes

The parts of setting up and using two-step verification: a QR code to scan, the same key to type, a one-time code field, and a sheet of recovery codes.

Standard componentContrast verifiedUnused in mocks

Overview

Members turn on two-step verification in Settings › Security, and staff must. Setup shows a QR code for an authenticator app with the same key as text, asks for a code to confirm, then shows ten recovery codes once. Sign-in asks for a code with the otp field. These parts always sit inside a form layout or an auth card with headings and instructions; they are not used alone. For a plain number field use a text field.

Not used in the mocks yet.

Anatomy

  1. QR code.qr, a fixed --size-qr square on --color-qr-bg (light in both themes so phones can scan it) holding a 21×21 SVG of rect modules. The SVG is hidden; the wrapper is role="img" named in words.
  2. Key.secret, the same secret as text in code type, grouped in fours, with a Copy button.
  3. One-time codeinput.input.otp, a centred, wide-spaced code field with inputmode="numeric" and autocomplete="one-time-code".
  4. Recovery codesol.codes, ten codes in two columns on a sunken panel; a used code (li.is-used) is struck through.

Focus rings the code field. Invalid marks the field and says what to do; the code is cleared so the next one can be typed. A used recovery code is struck through and announced as used.

Responsive behaviour

The QR code keeps its size at every width; at 360px it sits above the key rather than beside it. Recovery codes stay in two columns down to 360px; code type keeps every code on one line. The code field stays short and centred.

Theming

Every colour comes from a semantic role, so the dark theme needs no component-specific rules. A light specimen nested under a dark root resets its roles.

Accessibility

Role: the QR code is an image named in words (its SVG is hidden). The key is text that can be selected and copied. The code field is a labelled text input with numeric input mode, not type="number", so leading zeros survive and no spinner appears. Recovery codes are an ordered list.

KeyEffect
TabMoves from Copy key to the code field.
Enter in the code fieldSubmits the code.

Focus: after a wrong code, focus returns to the cleared field with the error linked through aria-describedby.

Labelling: the field's label says where the code comes from ("6-digit code from your app"). Used recovery codes carry visually hidden "Used:". The copied key is confirmed in a polite status.

Motion: none.

Touch: inputmode="numeric" opens the number pad and autocomplete="one-time-code" lets the phone fill the code from a message.

Content

Explain each step in one sentence: Scan this code with your authenticator app. Can’t scan it? Enter this key. Group the key in fours: K7QM 4XTB 9RHD 2WPL. Recovery codes are two groups of four: 4KQ7-9XTB. Tell people to keep codes somewhere safe, and that each works once.
