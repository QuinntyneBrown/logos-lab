Switch

Turn a setting on or off the moment it is touched — a sage track for on, a quiet grey track for off.

Core componentContrast verified

Overview

Use a switch for a setting that takes effect immediately, with no Save button: notifications, the dark theme, showing weekends. If the change only applies when a form is submitted, use a checkbox. If there are more than two positions, use a radio group or a segmented button group. Switches live in settings lists, one per row, with a hairline between rows.

Kit component; mocks have not been written yet.

Anatomy

  1. Row.switch: a two-column grid with a hairline under it, so a list of settings reads as one column.
  2. Title.switch__title, the name of the setting; a label linked to the control.
  3. Descriptionoptional .switch__text, what the setting does, linked with aria-describedby.
  4. Track.switch__control: a native checkbox with role="switch", 44 × 28px, sage when on.
  5. Thumba 20px surface dot that sits left for off and right for on.

Sizes

One size. The track is 44 × 28px (--size-switch-width × --size-switch-height) and the row is at least 44px tall.

States

Off is a grey track with the thumb on the left; hover darkens it. On (checked) is a sage track with the thumb on the right; hover deepens the sage. Focus draws the sage ring around the track. Disabled uses the linen track and greys the title and description. While a change is saving, keep the switch in its new position and show progress beside it with an inline message; if saving fails, move it back and say why.

Responsive behaviour

The row is a two-column grid at every width: text takes the remaining space and wraps, the switch stays the same size at the end. .switch--label-right keeps the switch first on any width. Settings lists fill their column; on phones they span the screen with the page margin.

Theming

Every colour comes from a semantic role, so the dark theme needs no component-specific rules. A light specimen nested under a dark root resets its roles.

Accessibility

Role: <input type="checkbox" role="switch">, announced as "switch, on" or "switch, off".

KeyEffect
Tab / Shift+TabMoves to and from the switch.
SpaceTurns the setting on or off. Enter does nothing, so it never submits a surrounding form.

Focus: the 2px sage ring, offset 3px, follows the pill shape of the track. Toggling never moves focus.

Labelling: the title is a label for the control (or the whole row is the label), and the description is linked with aria-describedby. The label names the setting and never changes with the state.

Motion: the track colour changes over 240ms; the thumb jumps rather than slides, and colour transitions are removed under reduced motion. In forced-colours mode the track gets a system-colour border.

Touch: the label row extends the target; the track itself is 44px wide.

Content

  • Name the setting, not the action: Weekly digest, Show weekends in the calendar — never "Turn on digest" or a label that flips to "Turn off".
  • Descriptions say what happens when it is on: "A Monday summary of what changed in Harbour Notes."
  • Do not add On/Off text beside the switch; the role announces the state and the track shows it.

Code

Use input.switch__control with type="checkbox" and role="switch". Wrap it with its text in .switch; link the title with for (or make the row a label) and the description with aria-describedby.

<div class="switch"><div><label class="switch__title" for="s669-sw-digest">Weekly digest</label><p class="switch__text" id="s669-sw-digest-text">A Monday summary of what changed in Harbour Notes.</p></div><input class="switch__control" id="s669-sw-digest" name="s669-digest" type="checkbox" role="switch" aria-describedby="s669-sw-digest-text"></div>
