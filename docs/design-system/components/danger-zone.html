Danger zone

Fence off the actions that cannot be undone, say exactly what will be lost, and ask for the name before acting.

Overview

A danger zone sits at the very end of a settings page and holds the actions that destroy or give away something: delete a project, leave a notebook, transfer ownership. A thin lingonberry border sets it apart without shouting. The explanation names what will be lost and for whom, and the most severe action asks people to type the thing's name before the danger button wakes up. Put the same confirmation in a dialog when the action starts elsewhere; never put a danger zone in the middle of a form.

Kit component; mocks have not been written yet.

Anatomy

  1. Container.danger-zone: 24px padding, --radius-lg, a hairline in --color-danger-border.
  2. Title.danger-zone__title, an h3 in the h4 role and --color-danger-fg: "Delete Northwind".
  3. Explanationa muted paragraph that lists what disappears and says it cannot be undone.
  4. Typed confirmationa form field whose label shows the exact name in a .typed-name chip.
  5. Actionone btn--danger that repeats the verb and the object, disabled until the name matches.
  6. Rowsoptional .danger-zone__rows with a .danger-zone__label, a line of text and one button each.

Sizes

one size. The zone fills its settings column; the confirmation field is capped at the short measure (44 characters) so the name stays close to the label.

States

Disabled is the resting state of a typed confirmation: the button stays disabled until the typed text matches exactly (case-sensitive, trimmed). Focus draws the sage ring on the field. Invalid appears only if someone presses Enter with the wrong name: the field turns lingonberry and says what to type. Busy keeps the label, adds a spinner and makes the field read-only until the work is done; then the page moves away with a toast.

Responsive behaviour

  • 360px: everything stacks; the field and the button fill the width, and rows put their button under the text.
  • 768px: rows place the text and the button side by side, with the button aligned to the end.
  • 1024px and up: unchanged; the zone stays within the settings column's measure.

Theming

The border reads --color-danger-border and the title --color-danger-fg (lingonberry 700 in light, 300 in dark). The button is --color-danger-solid with --color-fg-on-danger. The typed-name chip reads --color-bg-subtle. The border is decorative: the title and the button carry the meaning.

Accessibility

Role: a <section> labelled by its title. The confirmation is an ordinary labelled text field; the button is a native <button> with disabled until the name matches.

KeyEffect
Tab / Shift+TabMoves to the field, then to the button once it is enabled.
EnterIn the field: deletes when the name matches, otherwise shows the error.
Enter, SpaceOn the button: performs the action.

Focus: the shared sage ring on the field and the button. After an error, focus stays in the field; after success, focus moves to the page heading of the screen people land on.

Labelling: the label includes the exact name ("Type Northwind to confirm"), and the error is linked with aria-describedby. The button names the verb and the object, never "Confirm". A busy zone sets aria-busy.

Motion: only the spinner turns while busy; under reduced motion it holds still and the label says "Deleting Northwind…".

Touch: the field is 52px tall and the button 44px; on phones the button spans the full width.

Content

  • Title: the verb and the object, "Delete Northwind", or "Danger zone" when it holds several rows.
  • Explanation: list what goes, with numbers, and who it affects: "removes its 48 tasks, 112 notes and every attached file for everyone on the team". End with "This can't be undone." only when it is true.
  • Offer the gentler path first: Archive before Delete, Transfer before Leave.
  • Button: repeat the verb and object, Delete Northwind; busy: Deleting Northwind….

Code

Link tokens/tokens.css and assets/components.css, then use this markup. The data-state attribute only forces a state for review; production code uses real interaction and native attributes.

<section class="danger-zone" aria-labelledby="s2147-dz-typed-title">
  <h3 class="danger-zone__title" id="s2147-dz-typed-title">Delete Northwind</h3>
  <p>Deleting Northwind removes its 48 tasks, 112 notes and every attached file for everyone on the team. This can't be undone.</p>
  <div class="field">
    <label class="field__label" for="s2147-dz-typed-name">Type <span class="typed-name">Northwind</span> to confirm</label>
    <input class="input" id="s2147-dz-typed-name" name="s2147-confirm-name" type="text" autocomplete="off" spellcheck="false" value="Northwind">
  </div>
  <div class="form-actions"><button class="btn btn--danger" type="button">Delete Northwind</button></div>
</section>
