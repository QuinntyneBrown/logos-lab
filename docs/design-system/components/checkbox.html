Checkbox

Turn one option on or off, or pick any number from a list — a soft square that fills with sage when chosen.

Overview

Use a checkbox for an independent yes-or-no answer that takes effect when the form is submitted ("Email me a copy"), or to pick any number of options from a list (filters, days, topics). For a setting that applies the moment it changes, use a switch. For exactly one answer from a list, use a radio group. Larger, described choices that people compare side by side can use the .choice card from the radio group with type="checkbox".

Not used in the mocks yet.

Anatomy

  1. Rowlabel.check: a 44px tall target that wraps the box and its text, with a linen wash on hover.
  2. Box.check__box: a native checkbox restyled as a 20px soft square; sage fill and a white tick when checked.
  3. Labelthe text that names the option; clicking it toggles the box.
  4. Descriptionoptional .check__desc second line inside .check__text.
  5. Countoptional .check__count at the end of the row, for filter results.

Sizes

One size. The box is 20px inside a 44px row, so the whole row is the target at every width.

States

Hover washes the row with linen and darkens the box border. Focus draws the sage ring around the box. Checked fills the box with sage and shows the tick; indeterminate shows a dash for a partly checked group. Disabled greys the box and the text and drops the hover wash; a disabled checked box keeps its tick on a grey fill. Invalid turns the box border to danger and adds an error message after the row.

Responsive behaviour

Rows fill their column and wrap long labels under themselves, never under the box. .check-grid is one column on phones and two from 40rem. Filter lists in a sidebar become a sheet on phones; the rows keep their 44px height.

Theming

Every colour comes from a semantic role, so the dark theme needs no component-specific rules. A light specimen nested under a dark root resets its roles.

Accessibility

Role: native <input type="checkbox"> inside its <label>. A partly checked parent sets the indeterminate property (announced as "mixed").

KeyEffect
Tab / Shift+TabMoves to and from each checkbox; every box is its own tab stop.
SpaceToggles the focused checkbox. A mixed parent becomes checked, which checks every child.

Focus: the 2px ring, offset 3px, sits on the box. Toggling never moves focus; filter results update around the list, and their new count is announced politely.

Labelling: wrap the box and its text in one label, so the whole row toggles it. Group related boxes in a fieldset with a legend that asks the question. Link a description with aria-describedby. Errors for a group are linked from the fieldset.

Motion: the tick fades in over 160ms and the row wash over 240ms; both are removed under reduced motion. In forced-colours mode the native checkbox is restored.

Touch: the whole 44px row is the target, not just the 20px box.

Content

  • Write labels as positive statements of what will happen when checked: Email me a copy of these notes, not "Don't email me".
  • Keep options parallel and short; put any consequence in the description.
  • Legends ask the question: Topics for Field Day, Status.
  • Never pre-check consent, marketing or sharing boxes.

Code

Wrap input.check__box and its text in label.check. Use .check__text with .check__desc for two lines, .check__count for filter counts, and a fieldset.check-group with a legend for a list. Set the indeterminate property from script (data-indeterminate="true" previews it).

<label class="check"><input class="check__box" type="checkbox" name="s579-copy"><span>Email me a copy of these notes</span></label>
