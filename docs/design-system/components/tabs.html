Tabs

Switch between a few views of the same thing without leaving the page. Muted labels on a hairline, the selected one underlined in sage.

Overview

Use tabs for two to six views of one object that people move between freely: a project's overview, notes and activity; a list filtered to all, mine or shared. Every tab shows the same kind of content and none depends on another. For steps that must happen in order, use a stepper; for the sections of a whole area, use a sidebar navigation; for a single on/off choice between modes, use a segmented button group.

Used in 1 mock state.

Anatomy

  1. Tab list.tabs with role="tablist" and a name; a hairline runs beneath it and it scrolls sideways when it overflows.
  2. Taba 44px button.tab in the label type style, muted until selected.
  3. Selection indicatora 2px sage underline under the selected tab (or a sage pill in .tabs--pill).
  4. Countoptional trailing badge.
  5. Panelrole="tabpanel", labelled by its tab; only the selected panel is shown.

Variants

Underline

The default: an underline marks the selected tab. Use it at the top of a page or card. Try the arrow keys.

Tabs · navigation tabs

Sizes

one size. Tabs are --target-comfortable (44px) tall in the label type style with --space-4 inline padding; the underline is --border-width-thick.

States

Unselected tabs rest in the muted text role. Hover adds the linen wash and the default text role; keyboard focus draws the sage ring. The selected tab takes the default text role and the sage underline (in .tabs--pill, the sage-tinted fill with accent text); it is announced with aria-selected="true". A disabled tab uses the disabled text role and is skipped by the arrow keys. The matrix forces each state on the first unselected tab.

Responsive behaviour

The tab list never wraps. When the tabs are wider than their container, at 360px for example, the list scrolls sideways with a swipe or the arrow keys, and the selected tab is scrolled into view on load. At 768px and 1024px and up most lists fit. Keep labels short so the first three tabs fit at 360px.

Theming

Every colour reads a semantic role. In dark mode the underline and the pill fill turn light sage; the hover wash is a lighter charcoal.

Accessibility

Role: role="tablist" (named with aria-label or aria-labelledby) of button role="tab", each with aria-selected and aria-controls pointing at its role="tabpanel"; the panel has aria-labelledby its tab and tabindex="0" when it holds no focusable content. This follows the WAI-ARIA APG tabs pattern with automatic activation. Navigation tabs are links with aria-current="page" instead.

KeyEffect
TabMoves focus into the tab list, onto the selected tab; the next Tab moves into the panel.
Right Arrow / Left ArrowMoves to and selects the next or previous tab, wrapping at the ends.
Home / EndMoves to and selects the first or last tab.
Enter, SpaceSelects the focused tab when activation is manual (use manual activation if a panel is slow to load).

Focus: a roving tabindex: only the selected tab is 0, the rest are -1. The focused tab shows the shared 2px --color-focus-ring.

Labelling: name the tab list after the object ("Northwind", "Tasks"). Counts are part of the tab's name; don't hide them. Icons are decorative.

Motion: the selection changes at once; nothing animates, so nothing to reduce.

Touch: tabs are 44px tall; a scrolling list scrolls with a swipe without selecting a tab.

Content

Label tabs with one or two nouns in sentence case: Overview, Notes, Shared with me. Keep the order stable and put the most-used view first. Don't number tabs, end them with punctuation, or write instructions ("Click to see files"). Counts are bare numbers: 12, never "(12)".

Code

Wrap the list and its panels together. Script switches aria-selected, the roving tabindex and the panels' hidden attribute; .tabs--pill changes only the look.
