Error page

When a whole screen cannot be shown, say so calmly, say what is safe, and offer the next step. A large quiet number, a plain title and a way out.

Overview

An error page replaces the whole main content when the screen cannot be shown: the page does not exist (404), the person may not see it (403), something broke on our side (500), the device is offline, or the service is down for planned work. The top bar and footer stay, so people are never stranded. For a part of the page that failed, use an empty state in its error form; for a problem people can fix in place, use an alert.

Not used in the mocks yet.

Anatomy

  1. Code or iconthe status number in the light display face, subtle and decorative; or an icon tile when there is no number (offline, maintenance).
  2. Titlethe page's single h1, saying what happened in plain words.
  3. Textone or two sentences in the large body style: why, what is safe, what to do.
  4. Actionsa primary way forward and at most two quiet alternatives; on a 404, a search field.

Sizes

one layout. The error page takes the main column with generous vertical space and keeps its text to the reading measure.

States

An error page is a state of the whole screen, so it has none of its own. Its actions follow the button states; "Try again" becomes busy while it retries, and the page is replaced by the real screen when it succeeds.

Responsive behaviour

At 360px the code shrinks with the display scale, the search field takes the full width and the actions wrap, one per line if needed. From 768px actions sit in one row. Content stays left-aligned at every width, under the top bar, so it reads like the rest of the product.

Theming

The code reads --color-fg-subtle, the title --color-fg-default and the text --color-fg-muted, all on the canvas, each with a dark value. The icon tile reads the accent-subtle pair.

Accessibility

Role: an ordinary page: one <h1 class="error-page__title"> inside <main>, and the document <title> repeats it ("We can't find that page · Northwind"). The server returns the real status code. The big number is aria-hidden="true"; the title says the same thing in words.

KeyEffect
Tab / Shift+TabMoves through the skip link, top bar, search and actions in order.
EnterSubmits the search or follows an action.

Focus: on a client-side route change to an error page, move focus to the h1 (with tabindex="-1"), as for any new page. Never trap focus.

Labelling: the search field has a label ("Search Northwind"); actions name where they go ("Back to Northwind").

Motion: none. The offline page may retry quietly in the background; it never animates.

Touch: actions are 44px buttons with at least 12px between them.

Content

Plain words, no codes in the title, no jokes: We can't find that page, This page is private, Something went wrong on our side, You're offline, Back at 3:00 am. The text says why, what is safe, and what to do. Use "we" for our failures; never blame the link-follower. Give a reference only on server errors, labelled so people know when to use it.

Do and don’t

Tokens

Error pages read the display font at --font-size-5xl, --text-h1, --text-body-lg, the subtle, default and muted text roles, --layout-measure and the spacing scale.

Code

Inside <main>, use .error-page with an .error-page__code (or an .empty__icon tile), an <h1 class="error-page__title">, .error-page__text and .error-page__actions. The documentation shows the title as h3 because each specimen sits inside this page; production pages use h1.
