Inline message

One short line beside the thing it is about — Saving…, All changes saved, Couldn't save. The smallest piece of feedback.

Overview

Use an inline message for a one-line status next to the control or content it describes: the save state in an editor toolbar, the result of a "Check availability" button, sync status under a list. It is quieter than an alert and does not leave like a toast. Field-level validation errors use the field's own error text in form field; a whole-page problem uses an alert.

Kit component; mocks have not been written yet.

Anatomy

  1. Indicatora 16px icon or a small spinner, coloured with the text.
  2. Messageone short sentence in --text-body-sm.
  3. Actionoptional: a text button that fixes the problem, such as Try again.

Sizes

one size, matching small body text so it sits on the same line as a btn--sm or a toolbar.

States

An inline message has no interactive states. It moves through its variants as the thing it describes changes: neutral → saving → success, then back to neutral after about 4 seconds; or saving → danger, which stays until the next attempt. Keep it in the same place so the text changes and nothing jumps.

Responsive behaviour

The message wraps onto two lines at 360px; keep it short enough that it rarely does. Beside a button it wraps under the button. It never truncates with an ellipsis, because the ending is often the important part.

Theming

Text and icon share one role per tone — --color-fg-muted, --color-success-fg, --color-warning-fg or --color-danger-fg — each with its own dark value.

Accessibility

Role: render the element once, empty, with role="status", then change its text, so screen readers announce each update politely. Do not use role="alert" for save status; it interrupts typing.

KeyEffect
Tab / Shift+TabSkips the message; reaches the action button if there is one.
Enter, SpaceActivates the action.

Focus: never move focus to an inline message.

Labelling: the text is the message; icons and spinners are aria-hidden. Do not announce every keystroke save — debounce to one "Saving…" and one result.

Motion: the spinner turns while saving and stops under reduced motion; the words remain.

Touch: an action beside the message keeps a 36px button.

Content

Use a few words, sentence case, no exclamation marks: Saving…, All changes saved, Saved 2 minutes ago. Failures say what is safe: Couldn't save. Your text is still here. Use the ellipsis character for ongoing work and a full stop only when there are two sentences.

Do and don’t

Tokens

Inline messages read the muted, success, warning and danger text roles, --text-body-sm, and the small icon size.

TokenLightDark
--space-2
--text-body-sm
--color-fg-muted
--color-success-fg

--color-warning-fg

Code

Use <p class="inline-status" role="status"> and swap the tone modifier and text as the state changes. Put a .spinner first while working, or an .icon.icon--sm for a result.
