Profile header

The top of a person's or a thing's own page. A square portrait or tile, a large name, one quiet line of context and the actions that belong to it.

Standard componentContrast verified

Overview

Use a profile header once, at the top of a page that is about one person or one thing: Amara's profile, the Northwind project, the Harbour Notes notebook. It names the subject, says in one line what it is, and holds the two or three actions that apply to the whole page. For the title of an ordinary screen (Settings, Projects) use a page header; for a person inside a list use a person list or a card.

Kit component; mocks have not been written yet.

Anatomy

  1. Portrait or tilea 96px square with soft corners: a photo (__photo), a person's initials (__initials) or a thing's mark (__mark) on a tile tone.
  2. Namethe page's heading (__name), set in the display face at the h1 size.
  3. Context lineone muted sentence (__sub): a role, or what the thing is.
  4. Metaoptional facts with small icons (__meta): presence, place, team size.
  5. Actionsone primary action and quiet secondaries (__actions). Rare and destructive actions go into a More menu (.more with a .menu).

Sizes

One size. The tile is 96px and the name uses the h1 role, so a profile page looks the same wherever it is reached from; only a narrow container scales it down. A smaller summary of a person is a card or an avatar.

States

Focus puts the shared sage ring on the action that has it (here the More button). Open shows the More menu below its button; on a live page it floats above the content. Loading keeps the header's shape with skeleton blocks so the page does not jump when the name arrives.

Responsive behaviour

The header is a size container. Below 34rem of its own width (every phone, and narrow columns on larger screens) the tile shrinks to 64px and sits above the name, which drops to the --font-size-3xl size, so long names wrap between words instead of inside them. From 34rem up the 96px tile sits beside the name. The actions always sit below and wrap onto a second line when needed. The header stays a single, left-aligned column at 1024px and up so the name lines up with the page content beneath. The More menu opens below its button and is never wider than the screen.

Theming

Every colour comes from a semantic role, so the dark theme needs no component-specific rules. A light specimen nested under a dark root resets its roles.

Accessibility

Role: a <header> at the top of the page's <main>, with the name as the page's only <h1>. The More control is a <details>/<summary> disclosure that reveals a group of links.

KeyEffect
Tab / Shift+TabMoves through the actions, then into the open menu's items.
Enter, SpaceOn More: opens or closes the menu. On an action: activates it.
EscapeCloses the open menu and returns focus to More (wire this in the app).

Focus: every action shows the 2px --color-focus-ring outline. When the menu closes, focus returns to the More button.

Labelling: a photo's alt names the person ("Portrait of Daniel Reyes"); initials and marks are decorative (aria-hidden="true") because the heading says the name. The More button carries an aria-label that names whose actions they are. Presence is text ("Online now"), not only a dot.

Motion: the menu appears without animation under reduced motion; the presence dot stops breathing.

Touch: actions are 44px pills; menu items are 44px tall.

Content

The name is the heading: Daniel Reyes, Northwind. Never prefix it with "Profile of". The context line is one sentence in plain words: Engineer on Northwind and Harbour Notes, A calm planning board for small teams. Action labels name the person or thing: Message Daniel, Ask to join, Edit profile. Put report and block in the More menu, with the person's name: Report Daniel.

Code

Use .profile-head with __who (tile plus __text) and __actions. Choose exactly one of __photo, __initials or __mark, and add a tile--* tone to initials and marks.
