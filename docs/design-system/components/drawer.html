Drawer and sheet

A panel that slides in from an edge for filters, navigation or detail, keeping the page it belongs to in view.

Overview

Use a sheet when people need a secondary surface while keeping their place: filters on a phone, the workspace navigation on a small screen, or the detail of one row beside a list. A bottom sheet suits phones and short, thumb-reachable choices; side drawers suit navigation (left) and detail (right). Use a dialog when the task must be finished or abandoned before anything else, and a popover for a small choice anchored to one control.

Not used in the mocks yet.

Anatomy

  1. Panelthe raised surface with --shadow-4, rounded on the edges that face the page.
  2. Headthe title (.sheet__title) and a close icon button (.sheet__head).
  3. Contentchoices, links or facts; the panel scrolls when it is taller than the window.
  4. Done actionoptional full-width primary button at the end (.sheet__done) that applies and closes.

Sizes

a bottom sheet is full width and at most 86% of the window tall; side drawers are --layout-aside-width (21rem) wide, or the full width on screens narrower than that.

States

Open is the only resting state; closed sheets are not rendered. Hover and keyboard focus show on the close button and every control inside, with the 2px sage ring for focus. Content that changes after a choice, such as the count in Show 8 projects, updates in place without moving the button.

Responsive behaviour

At 360px the bottom sheet is the default overlay for filters and item actions, with the done button at thumb height. From 768px filters move into the page (a sidebar or toolbar) and bottom sheets are rarely needed. The left drawer replaces the sidebar below 1024px; from 1024px the sidebar is always visible and the drawer is not offered. The right drawer overlays the list below 1024px and may sit beside it on wider screens.

Theming

Sheets use --color-bg-surface-raised over the --color-bg-backdrop scrim with --shadow-4. In dark mode the raised surface is lighter than the page, so the edge stays visible without a border.

Accessibility

Role: in production a sheet is a modal dialog — a <dialog> opened with showModal(), or an element with the popover attribute for light-dismiss filters — labelled by its title. It follows the APG modal dialog pattern. The static specimens here use role="region" so they can sit in the page.

KeyEffect
Tab / Shift+TabMoves through the sheet's controls; focus stays inside while it is open.
EscapeCloses the sheet and returns focus to the button that opened it.
Enter, SpaceActivates the focused control; the done button applies and closes.

Focus: on open, focus moves to the close button (navigation, detail) or the first choice (filters). On close it returns to the trigger — the menu button, the filter button or the row that was opened.

Labelling: name the trigger after what opens (Filters, Menu) and give it aria-expanded and aria-controls. Label the close button after what it closes: Close filters, Close menu.

Motion: the sheet settles in over --duration-slow with --ease-enter; under reduced motion it appears in place, and the backdrop never animates.

Touch: rows and links are 44px tall; the done button is a full-width 44px pill within thumb reach.

Content

Title the sheet with what it holds: Filter projects, Harbour Notes, the person's name. Make the done button state the outcome: Show 8 projects, not Apply or Done when a count is known. Name each action with a verb and the object: Rename notebook, Delete notebook.

Code

Add sheet--bottom, sheet--left or sheet--right to .sheet. In production put it on a <dialog> or an element with popover, and wire the trigger's popovertarget or a showModal() call.
