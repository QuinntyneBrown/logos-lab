Description list

Pairs of small uppercase labels and plain values, for the facts about a person, project or gathering.

Overview

Use a description list for read-only facts that each have a name: who owns a project, when a gathering starts, someone's role and local time. It is quieter than a table and keeps label and value together when the layout reflows. Use a table to compare the same facts across several items, and a form when the values can be edited in place.

Used in 1 mock state.

Anatomy

  1. Termthe label, in the overline style: small, uppercase, widely tracked, --color-fg-subtle.
  2. Valuethe fact in body text; long values wrap.
  3. Paira <div> that keeps one term with its value, --space-1 apart.
  4. Rhythm--space-4 between pairs; inline lists add a hairline under each pair.

Labels above values, in one column. The default for asides and narrow cards.

Sizes

one size. Terms use the overline style and values use body text; inside cards use .card__facts, which sets values in body-small.

States

Description lists are read-only, so they have no hover or focus of their own; links inside them behave like any link. While the facts load, each value is replaced by a skeleton line and the terms stay, so people can see what is coming.

Responsive behaviour

Stacked lists are the same at every width. Inline lists keep label and value side by side (one third and two thirds) down to 360px, where long values wrap under themselves. Column lists fit as many 10rem columns as their container allows: one at 360px and up to four from 768px.

Theming

Terms use --color-fg-subtle, values --color-fg-default, hairlines --color-border-default; all are semantic roles, so the list needs no dark-mode rules.

Accessibility

Role: a native <dl> with each <dt>/<dd> pair wrapped in a <div>, which HTML allows and which keeps pairs together in grid layouts. Screen readers announce the list and its number of terms.

Labelling: terms are real text, uppercase only through CSS, so they are read normally. Give a list a heading (such as At a glance) when it stands alone. Missing values are written out (Not added yet) so nothing is announced as blank.

Motion: none; skeletons stop shimmering under reduced motion.

Touch: links inside values keep a comfortable line height; put no more than one link in a value.

Content

Terms are one or two words in sentence case before the CSS uppercases them: Owner, Local time. Values are short facts, not sentences: 4 people, Saturday 17 October 2026, 10:00 am. Use the same format for the same kind of value everywhere. Write missing values as Not added yet, never a dash.

Do and don’t

Tokens

Description lists read the overline and body type roles, the subtle and default text roles, the hairline border and --space-1 to --space-6 gaps.

Code

Use <dl class="facts"> and wrap each pair in a <div>. Add facts--inline or facts--columns for the other layouts, and class="is-empty" on a <dd> with no value.

<dl class="facts">
  <div><dt>Owner</dt><dd>Amara Osei</dd></div>
  <div><dt>Members</dt><dd>4 people</dd></div>
  <div><dt>Started</dt><dd>March 2026</dd></div>
</dl>
