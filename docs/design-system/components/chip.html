Chip and tag

Narrow a list with one tap. A pressed chip turns sage; an applied filter shows as a chip you can remove.

Overview

A chip is a toggle button for filtering: Design, Engineering, Within 10 km. Pressing it adds the filter and turns it sage; pressing again removes it. A row of chips sits above a list or in a search and filter toolbar. An applied filter that came from elsewhere (a search, a link) shows as a removable chip. Use a badge or tag for a label people cannot change, tabs to switch between views, and a radio group when exactly one option must be chosen in a form.

Used in 1 mock state.

Anatomy

  1. Leading iconoptional, 16px, decorative.
  2. Labelone to three words naming the filter.
  3. Countoptional, the number of results the filter would show, in subtle tabular figures.
  4. Containera 36px pill with a hairline border; pressed chips fill with --color-accent-subtle and an accent border.
  5. Removeon applied filters only: a 24px round button that names the filter.

Sizes

chips have one 36px height so a row of filters lines up. The pill grows with its label; the whole chip is the target, and it never drops below the 24px minimum.

States

Hover adds a linen wash and a stronger border; active deepens the wash while pressed; focus shows the sage ring. Pressed (aria-pressed="true") fills the chip with the accent tint and an accent border, and stays that way until pressed again. A disabled chip — a filter with no results right now — is greyed out and keeps its count of 0 so people can see why.

Responsive behaviour

A .chips row wraps at every width with an 8px gap; it never scrolls sideways out of sight. At 360px, long filter sets collapse into a "Filters" button that opens a drawer, and the applied filters show as removable chips above the list. From 768px the full row fits beside the search field.

Theming

Chips read surface, border and accent roles. In dark mode the pressed fill becomes a deep sage tint with light sage text; the hairline border keeps 3:1 against the surface. In forced-colours mode each chip gets a CanvasText border.

Accessibility

Role: a native <button type="button" aria-pressed> for each filter, inside a role="group" with an aria-label that names the filter set. Removable chips are plain text with a real remove <button>.

KeyEffect
Tab / Shift+TabMoves between chips; every chip is a stop.
Enter, SpaceToggles the chip and updates aria-pressed.
Enter, Space on removeRemoves the filter; focus moves to the next chip, or to the list heading when none are left.

Focus: the shared 2px --color-focus-ring, offset 3px, around the pill.

Labelling: the label never changes when pressed — aria-pressed carries the state. Counts are read as part of the name ("Research 12"); if that is unclear, add a .vh "notes". Remove buttons say "Remove filter: tagged research". After the list updates, announce the new total in a role="status" message ("14 notes").

Motion: background and border fade over 240ms; reduced motion swaps them instantly.

Touch: 36px tall with at least an 8px gap between chips.

Content

Name the filter, not the action: Research, This week, Within 10 km — not "Show research". Use sentence case, one to three words, no punctuation. Counts are bare numbers. Applied filters read as a short phrase: Tagged research, Last 7 days, Daniel Reyes.

Code

Use <button class="chip" aria-pressed="false"> inside a .chips group. Add .chip__count after the label, a leading .icon.icon--sm, or a .chip__remove button for applied filters.
