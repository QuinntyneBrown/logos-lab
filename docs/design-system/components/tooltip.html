Tooltip

A few words on a dark chip that appear on hover or keyboard focus, to explain a control without adding to the page.

Core componentContrast verified

Overview

Use a tooltip to add a short description to a control whose purpose is clear but whose detail is not: what an icon button affects, a keyboard shortcut, why an action is unavailable, the exact time behind "2 min ago". The control must still make sense without it. Never put anything essential, interactive or longer than one line in a tooltip; use an explainer popover for that, and inline text for anything people must read.

Not used in the mocks yet.

Anatomy

  1. Triggera focusable control, usually an icon button, that references the tooltip with aria-describedby.
  2. Chipthe inverse surface with small radius and caption text (.tooltip), 8px above the trigger.
  3. Shortcutoptional <kbd> at slightly lower emphasis inside the chip.

Variants

Icon button

The most common use: an icon button keeps its aria-label as its name, and the tooltip adds a short description.

Sizes

one size. Caption text with --space-2 by --space-3 padding; the chip is as wide as its single line.

States

Default is hidden. Hover shows the tooltip alongside the trigger's own hover wash; focus shows it with the sage focus ring on the trigger. Escape hides it until the pointer or focus moves away and back.

Responsive behaviour

Tooltips behave the same at every width, but touch screens have no hover: on phones they appear only on keyboard focus. Never rely on them for anything a phone user needs; at 360px put that text on the page or in an explainer popover. The chip opens above the trigger and aligns to its start edge; keep triggers clear of the right edge so a long chip does not run off screen.

Theming

The chip inverts the theme: --color-bg-inverse with --color-fg-inverse, near-black on light pages and near-white on dark ones, so it always stands apart from the surface beneath it.

Accessibility

Role: role="tooltip" on the chip, referenced by the trigger's aria-describedby. It follows the APG tooltip pattern. The tooltip describes; the trigger is still named by its own text or aria-label.

KeyEffect
Tab / Shift+TabFocusing the trigger shows the tooltip; leaving hides it.
EscapeHides the tooltip while focus stays on the trigger.

Focus: the tooltip never takes focus and holds nothing focusable. It stays visible while the pointer is over the trigger or the chip itself, and until focus leaves, so people who zoom can read it (WCAG 1.4.13).

Labelling: don't repeat the trigger's name in the tooltip; add what the name leaves out. A disabled reason only works on an aria-disabled button, because a disabled button cannot be focused.

Motion: the chip appears and disappears without animation.

Touch: tooltips cannot be the only way to learn something on touch screens. Icon buttons with tooltips keep their 44px target.

Content

One line, no full stop, sentence case: Anyone in Northwind can open it, Add a title before publishing. Write shortcuts as people type them: Ctrl K. Give exact times in full: Friday 9 October 2026, 9:42 am. If it needs two sentences, it is not a tooltip.

Code

Wrap the trigger and the chip in .tooltip-anchor; the chip shows on :hover and :focus-within, and Escape sets data-dismissed on the anchor. data-state="open" pins it open for review only.
