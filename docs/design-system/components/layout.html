Container, grid and stack

The layout primitives every page is built from. A centred container, vertical stacks, wrapping clusters, an auto-fit grid and the page's column patterns.

Overview

These classes place components; they have no colour or content of their own. Build every page from them instead of writing one-off margins: .wrap sets the page container, .stack spaces things vertically, .cluster lines things up in a wrapping row, .grid tiles cards, and .two-col, .split and .sidebar-layout are the three page shapes. .section with .section__head opens each band of a long page. Spacing comes only from the spacing and layout tokens, so pages stay on one rhythm.

Kit component; mocks have not been written yet.

Anatomy

  1. Container.wrap: full width up to --layout-container-max (74rem) plus the responsive --layout-margin on each side, centred. .narrow caps a block at --layout-narrow (44rem) for forms and prose.
  2. Stack.stack: a one-column grid with --space-4 between children; .stack--lg uses --space-8.
  3. Cluster.cluster: a wrapping row with --space-3 gaps, centred vertically; .cluster--between pushes the ends apart.
  4. Grid.grid: as many columns of at least --layout-card-min (18rem) as fit, with the --layout-gutter between them.
  5. Page shapes.two-col (content and a 21rem aside), .split (a 22rem list pane and detail), .sidebar-layout (a 17rem sidebar and content); all one column below 64rem.
  6. Section.section adds the section gap above; .section__head holds an eyebrow, a .section__title and an optional .section__more link.

Sizes

the primitives have no sizes of their own. Spacing steps are fixed (.stack --space-4, .stack--lg --space-8, .cluster --space-3); the container margin grows with the viewport through --layout-margin.

States

Layout has no interactive states. The one row in the matrix shows that a cluster is the same in both themes: layout never changes colour.

Responsive behaviour

  • 360px: --layout-margin is --space-5; every page shape is one column with the aside, list pane or sidebar after the content; .grid shows one column; clusters wrap.
  • 768px: --layout-margin is --space-10; .grid shows two columns; .section__head puts the more link at the trailing edge.
  • 1024px and up: --layout-margin is --space-16; .two-col, .split and .sidebar-layout become two columns; .grid shows three or four columns; the container stops growing at 74rem.

Accessibility

Role: none. Layout classes go on the element whose meaning fits: <section> with aria-labelledby for a section, <aside> for an aside, <nav> for a sidebar, <ul> for a list of cards.

Focus: source order is reading and focus order. Every page shape keeps the main content first in the source, so keyboard and screen reader users reach it before the aside; never reorder with order or grid-area against the source.

Labelling: name every <section> by its visible heading. Headings follow the page's outline, whatever their size.

Motion: none.

Touch: clusters keep a --space-3 gap, so adjacent small targets keep at least 8px between them.

Code

Compose primitives rather than adding margins: a page is usually .wrap > page header > .two-col (or .split, .sidebar-layout) > .stack of sections.

<div class="stack"><article class="card"><h3 class="card__name">Northwind</h3><p class="card__text">Launch checklist, 14 of 18 done.</p></article><article class="card"><h3 class="card__name">Harbour Notes</h3><p class="card__text">148 notes, 12 edited this week.</p></article><article class="card"><h3 class="card__name">Field Day</h3><p class="card__text">Saturday 17 October, 18 going.</p></article></div>
