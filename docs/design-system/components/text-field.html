Text field

A single line of typed answer, from a project name to a password, plus the signature search pill.

Overview

Use a text field for a short, single-line answer: a name, an email address, a number, a link. Use a textarea when the answer is a sentence or more, a select when there is a short fixed list, and a slider only when an approximate value is fine. Every text field sits in a form field with a visible label. The search pill is the one exception: it lives in toolbars and heroes with a visually hidden label and its action inside the pill.

Used in 7 mock states.

Anatomy

  1. Labelfrom the surrounding .field; always present, visible except in the search pill.
  2. Container.input: a 52px rounded rectangle with a hairline strong border on the surface.
  3. Value or placeholderbody text; the placeholder is a subtle example, never instructions.
  4. Addonoptional .input-group__addon before or after the input for a unit or a fixed prefix.
  5. Trailing actionoptional quiet button in an .input-group: Show password, Add, Send invite.

Sizes

lg (52px) is the default and the size for every form. md (44px) suits filters, toolbars and dialogs with several short fields; sm (36px) is only for dense table rows and inline edits on desktop. Keep one size per form. The search pill is one size: 44px controls inside a pill.

States

Hover darkens the border to the muted role. Focus draws the 2px sage ring offset 3px. Read-only fills with linen, softens the border and keeps full-strength text that can still be selected and is submitted. Disabled also fills with linen but drops the border and fades the text; it is skipped by the form, so prefer read-only to show a fixed value. Invalid turns the border to danger, tints the fill and adds an error message linked by aria-describedby.

Responsive behaviour

Text fields fill their column at every width. In an .input-group, the input shrinks and the addon or button keeps its natural width; on a 360px screen, keep addons to a short unit and buttons to one or two words. The search pill caps at --layout-narrow (44rem) and keeps its button inside the pill at every width.

Theming

Every colour comes from a semantic role, so the dark theme needs no component-specific rules. A light specimen nested under a dark root resets its roles.

Accessibility

Role: native <input> with the right type (text, email, password, number, url, search) and autocomplete token. The search pill is a <form role="search">.

KeyEffect
Tab / Shift+TabMoves into and out of the field, then to any trailing button.
Arrow keys, Home, EndMove the caret; in a number field, Up and Down change the value by one step.
EnterSubmits the surrounding form; in the search pill it runs the search.
EscapeIn a search field, clears the query. Never clears any other field.

Focus: the ring sits on the input itself, or around the whole pill for search. Never move focus on its own while someone types.

Labelling: a visible <label for> for every field; the search pill uses a .vh label that matches its placeholder. Units and prefixes are linked with aria-describedby so they are read with the value. The password toggle is a separate button whose label says what it will do: Show password, Hide password.

Motion: border and fill changes take 240ms and disappear under reduced motion.

Touch: 52px tall by default and never below 36px. Set inputmode and type so phones offer the right keyboard, and do not block zoom.

Content

  • Label the thing, not the action: Email address, not "Enter your email".
  • Placeholders show a real example in the expected format (amara@example.com), never instructions and never the label repeated.
  • Units belong in an addon: hours a week, km, harbournotes.app/, so the value stays a plain number or slug.
  • Errors name the fix: "Use at least 12 characters", "Enter a number from 0 to 60".

Do and don’t

Tokens

Text fields read the surface, default and subtle text roles, the strong border (darkening to muted on hover), the danger roles for invalid, the control heights and the medium radius. Override --ll-field-border to tint a single field without a new class.

Code

Use .input inside a .field; add .input--md or .input--sm only in dense layouts. Wrap an input and its addon or button in .input-group. The search pill is form.search with a .search__input and a .vh label.

<div class="field"><label class="field__label" for="s417-tf-name">Project name</label><input class="input" id="s417-tf-name" name="s417-project-name" type="text" value="Northwind" autocomplete="off"></div>
