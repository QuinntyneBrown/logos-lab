Select

Pick one answer from a short, known list — a native select with the kit's pill or field styling and a quiet chevron.

Overview

Use a select when people choose one option from a list of roughly 5 to 15 items they already understand: a project lead, a sort order, a reminder time. With four or fewer options, show them all with a radio group or a segmented button group. For long lists that people search, use a combobox built on the text field. For several answers, use checkboxes. The control is always the native <select>, so the platform's picker, keyboard and screen reader support come for free.

Kit component; mocks have not been written yet.

Anatomy

  1. Labelvisible text: inline beside the pill (.select > span) or above it in a .field.
  2. Control.select__control: the native select, a pill inline and a rounded rectangle in a field.
  3. Chevron.select__chev, a decorative 16px icon that never takes clicks.
  4. Wrapper.select__wrap positions the chevron over the control.

Sizes

The inline pill comes in sm (36px) for dense toolbars, md (44px, default) and lg (52px) to sit beside large buttons. Inside a .field, the select always takes the 52px field height so it lines up with text fields.

States

Hover darkens the border and adds a linen wash, like a quiet button. Focus draws the sage ring; while the native list is open (active) the border thickens in the focus colour. Disabled fills with linen and uses the disabled text role. Invalid turns the border to danger, tints the fill and adds an error message under the control. The empty placeholder option reads in the subtle role so it is not mistaken for an answer.

Responsive behaviour

Inline pills keep their label beside them and wrap to the next line of a toolbar rather than shrinking. Field selects fill their column at every width. On phones the native picker takes over (a wheel or a sheet), so option text must make sense on its own without the label.

Theming

Every colour comes from a semantic role, so the dark theme needs no component-specific rules. A light specimen nested under a dark root resets its roles.

Accessibility

Role: native <select> (combobox with a listbox popup). Never rebuild it from divs.

KeyEffect
Tab / Shift+TabMoves to and from the select.
Up / DownChanges the selected option (Windows) or opens the list (macOS).
Alt+Down, Space, EnterOpens the list.
Type a letterJumps to the next option starting with that letter.
EscapeCloses the list without changing the value.

Focus: the 2px sage ring follows the pill or the field shape. Changing the value never moves focus or submits the form; apply a sort or filter with the new value, but keep focus on the select.

Labelling: a visible label, either wrapping the inline pill (label.select) or linked with for. The chevron is aria-hidden. Help and errors are linked with aria-describedby.

Motion: only the border colour transitions (240ms), and not at all under reduced motion.

Touch: 44px tall inline and 52px in a field. The chevron sits inside the control's target and passes clicks through with pointer-events: none.

Content

  • Labels are nouns: Project lead, Sort by, Remind me.
  • Options are short, parallel and in a meaningful order: by time (The day before, Two hours before), by frequency of use, or alphabetically for names.
  • A placeholder option is a prompt, not an answer: Choose when. Never "Select…" or "-- Please select --".
  • Include the "none" answer as a real option (No reminder) rather than leaving the select empty.

Do and don’t

Code

Inline: label.select with a span label and a .select__wrap. In a form: put .select__wrap inside a .field with a label for. Add select--sm or select--lg to the control (or the .select) for size.

<label class="select"><span>Sort by</span><span class="select__wrap"><select class="select__control" name="s524-sort"><option selected>Recently updated</option><option>Name</option><option>Date created</option></select><svg class="icon icon--sm select__chev" viewbox="0 0 24 24" aria-hidden="true"><path d="m7 10 5 5 5-5"></path></svg></span></label>
