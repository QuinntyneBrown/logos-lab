Sidebar navigation

A vertical list of places inside one area of the product. Muted rows, a sage-tinted current page, and optional groups and counts.

Core componentContrast verified

Overview

Use a sidebar navigation when one area of the product has more destinations than the top bar should carry: the sections of a workspace, the projects someone belongs to, the pages of settings. It sits in the first column of a .sidebar-layout or .settings-layout and stays put while the content changes. For two to five views of the same object, use tabs instead; for a trail back up a hierarchy, use a breadcrumb. Never use it for actions; those belong in buttons or a menu.

Used in 1 mock state.

Anatomy

  1. Landmarka <nav> named for what it navigates: Workspace, Settings, Northwind.
  2. Group labeloptional .sidebar-nav__group overline that names a set of links.
  3. Itema 44px row: optional 20px icon, a label, and an optional trailing badge count.
  4. Current itemaria-current="page", on the sage tint with the accent text role.
  5. Collapsible groupoptional <details> whose <summary> hides a set of links until opened.

Sizes

one size. Rows are --target-comfortable (44px) tall with --space-3 inline padding; the column is --layout-sidebar-width (17rem) in .sidebar-layout and --layout-settings-nav (14rem) in .settings-layout.

States

Links rest in the muted text role. Hover adds the linen wash and lifts the label to the default text role; keyboard focus draws the sage ring around the row. The current page sits on --color-accent-subtle with --color-fg-accent text and stays tinted while hovered. A collapsed <details> group shows only its summary row. The matrix forces each state on the first link that is not the current page.

Responsive behaviour

  • 360px: a workspace sidebar collapses behind the top bar's Menu button or into a sheet; .settings-nav becomes a single row that scrolls sideways, keeping the current link in view.
  • 768px: the same as 360px, with room for more of the settings row.
  • 1024px and up: .sidebar-layout and .settings-layout place the nav in a fixed first column; .settings-nav stacks vertically.

Theming

Every colour reads a semantic role. In dark mode the current item's tint turns deep sage with light sage text; the hover wash is a lighter charcoal.

Accessibility

Role: a <nav> landmark with a unique aria-label, containing plain links (or a list of links). Group labels name their list with aria-labelledby. Never use role="menu" or role="tree" here: these are links, reached with Tab.

KeyEffect
Tab / Shift+TabMoves from link to link, including the summary of a collapsible group.
EnterFollows the focused link.
Enter, Space (on a summary)Opens or closes the group.

Focus: the 2px --color-focus-ring, offset 3px, wraps the whole row. In a scrolling .settings-nav, scroll the focused link into view.

Labelling: mark the current page with aria-current="page"; the tint alone says nothing to a screen reader. Put unread counts inside the link with a visually hidden word ("4 unread"). Icons are decorative.

Motion: none beyond the shared colour transition; nothing to reduce.

Touch: rows are 44px tall and span the column; the settings row scrolls with a swipe.

Content

Label destinations with nouns in sentence case: Projects, Notifications, Billing. Keep labels to two words and avoid verbs ("Manage billing" is a button). Name groups by what they hold: Your projects, Notebooks. Show counts only for things that need attention, and cap them at 99+.

Do and don’t

Tokens

Rows read the muted, default and accent text roles, the subtle and accent-subtle washes, --radius-md and --target-comfortable; layouts read --layout-sidebar-width and --layout-settings-nav.
